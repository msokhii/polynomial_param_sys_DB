The database of scalable parametric linear systems

This collection is for benchmarking algorithms that solve A(y) x = b(y) by evaluating the parameters in a finite field, solving the resulting numerical linear systems, and reconstructing the entries of x as multivariate rational functions. The organization follows the spirit of Jan Verschelde's PHCpack demonstration database: a compact system index, a characteristic table, precise definitions, and benchmark guidance.

Inclusion rule. Every family below is (i) linear in the unknown vector x, (ii) scalable to a genuinely large matrix, (iii) polynomial in one or more symbolic parameters, and (iv) generically nonsingular. There are no singular-kernel examples and no matrices with rational entries that first have to be cleared. Unless a natural application right-hand side is stated, use the fixed integer vector b = [1,2,...,N]^T; it adds no parameters and avoids some accidental symmetries.

Short description of systems

The first six are structured matrix families; R1–R3 are algebraic/resultant families; P1–P5 come from scalable applications.

N is the number of unknowns/equations. m counts symbolic parameters only; the fixed benchmark right-hand side is not included. “Max input degree” is total degree in the parameters of an entry of A or b.

Best four to start with: S1 (your current flagship), S4 (large matrix while keeping parameter count small), P1 (hard many-parameter graph problem), and P2 (hundreds of equations with only three parameters). Together they separate the effects of matrix dimension, number of parameters, and rational-output complexity much better than a collection of small unrelated examples.

System definitions

S1

Symmetric Toeplitz

primary dense benchmarktop
N=n · m=n · degree=1 · dense
A[i,j] = t[|i-j|], 1 ≤ i,j ≤ n b[i] = i

Parameters. t₀,…,tₙ₋₁.

Suggested sweep. n = 8, 12, 16, 20, then increase until probe count or reconstruction dominates.

Why use it. This is the cleanest baseline for the whole database: the matrix is dense, every entry is linear in the parameters, the parameter count grows with n, and setting t₀=1 with all other tᵢ=0 gives the identity, so the family is generically nonsingular.

S2

General Toeplitz

many parameterstop
N=n · m=2n−1 · degree=1 · dense
A[i,j] = t[j-i], −(n−1) ≤ j−i ≤ n−1 b[i] = i

Parameters. t₋ₙ₊₁,…,t₋₁,t₀,t₁,…,tₙ₋₁.

Why use it. It keeps the same dense Toeplitz geometry as S1 but roughly doubles the parameter count. Compare S1 and S2 at the same n to isolate the cost of additional variables in the reconstructed rational functions.

S3

Hankel

dense structuredtop
N=n · m=2n−1 · degree=1 · dense
A[i,j] = h[i+j-2], 0 ≤ i+j−2 ≤ 2n−2 b[i] = i

Parameters. h₀,…,h₂ₙ₋₂. Choosing hₙ₋₁=1 and all other hᵢ=0 gives the reversal permutation matrix, hence the determinant is not identically zero.

Why use it. It has the same parameter count as S2 but a different repeated-entry pattern. This makes S2 versus S3 a useful structure comparison without changing n or m.

S4

Banded Toeplitz

large-N benchmarktop
N=n · m=2w+1 · degree=1 · sparse
A[i,j] = t[j-i] if |j-i| ≤ w, = 0 otherwise. b[i] = i

Parameters. t₋w,…,t₀,…,t_w. Treat bandwidth w as a second benchmark knob.

Why use it. This is the simplest way to make the numerical solve large without simultaneously making the interpolation dimension large. Hold w fixed and grow n. It is therefore one of the most important complements to S1.

S5

Block Toeplitz with Toeplitz blocks (BTTB)

2-D structuredtop
N=q² · m=(2q−1)² · degree=1 · dense
Index rows/columns by grid pairs (r,c),(u,v) ∈ {0,…,q−1}². A[(r,c),(u,v)] = τ[u-r, v-c]. b[k] = k+1.

Parameters. One τa,b for each offset −(q−1)≤a,b≤q−1.

Why use it. This is the natural two-dimensional analogue of general Toeplitz. The matrix dimension grows quadratically in q while the number of shift parameters also grows on the order of N. It is a strong dense many-parameter stress test.

S6

Generic tridiagonal / continuant family

sparse many-parametertop
N=n · m=3n−2 · degree=1 · sparse
A[i,i] = d[i] A[i,i+1] = u[i] (1 ≤ i < n) A[i+1,i] = l[i] (1 ≤ i < n) all other entries = 0 b[i] = i

Parameters. d₁,…,dₙ, u₁,…,uₙ₋₁, l₁,…,lₙ₋₁.

Why use it. Parameter count is very high relative to matrix sparsity. It separates “many interpolation variables” from “expensive dense finite-field solve.” The determinant obeys the standard continuant recurrence, so this is also easy to validate independently.

R1

Sylvester resultant matrix

algebraic benchmarktop
N=r+s · m=r+s+2 · degree=1 · structured
f(z) = a₀ + a₁z + ··· + aᵣzʳ g(z) = b₀ + b₁z + ··· + bₛzˢ A = Sylvester(f,g) ∈ Z[a,b]^(r+s)×(r+s) b[k] = k

Parameters. a₀,…,aᵣ,b₀,…,bₛ. For a balanced sweep use r=s.

Why use it. The determinant is the resultant of two generic polynomials. This gives a very natural algebraic denominator rather than an arbitrary random one, and the family scales directly by increasing the polynomial degrees.

R2

Bézout matrix of two generic polynomials

degree-2 inputtop
N=q · m=2q+2 · degree=2 · dense
f(z)=Σ(i=0..q) aᵢ zⁱ, g(z)=Σ(i=0..q) bᵢ zⁱ (f(x)g(y) − f(y)g(x))/(x−y) = Σ(i=1..q) Σ(j=1..q) B[i,j] x^(i−1) y^(j−1) A = B(f,g), b[k]=k

Why use it. Unlike most families here, the matrix entries themselves are bilinear in the parameters. This is a controlled test of the effect of input degree 2 while retaining a canonical resultant structure.

R3

Companion resolvent

large sparse controltop
N=n · m=n+1 · degree=1 · sparse
f(z)=zⁿ+a[n−1]z^(n−1)+···+a₁z+a₀ C = companion matrix of f A(s,a) = s I − C b[i] = i det(A)=f(s).

Parameters. s,a₀,…,aₙ₋₁.

Why use it. This is a deliberately structured control case: N can be pushed very high, the matrix has only O(N) nonzeros, and the exact denominator is known. It is useful for checking whether failures are caused by your reconstruction machinery rather than by an intrinsically difficult matrix family.

P1

Grounded weighted q×q grid Laplacian

hard graph benchmarktop
N=q²−1 · m=2q(q−1) · degree=1 · sparse
Let G be the q×q nearest-neighbour grid, with one parameter w[e] per edge. L[v,v] = Σ(e incident to v) w[e] L[u,v] = −w[{u,v}] if u and v are adjacent, else 0. A = L with one ground vertex row/column deleted. b = e_source.

Parameters. One independent edge weight for each of the 2q(q−1) grid edges.

Why use it. The determinant of the grounded Laplacian is the weighted spanning-tree polynomial. The number of monomials can grow extremely quickly, so this is an excellent “output complexity” stress test for sparse rational reconstruction. Start small: q=4 or 5 may already be substantially harder than its matrix dimension suggests.

P2

2-D convection–diffusion finite-difference system

hundreds of equations / 3 paramstop
N=q² · m=3 · degree=1 · sparse five-point stencil
On a q×q interior grid with Dirichlet boundary conditions, use the stencil north: −2+β west: −2−α center: 8+2γ east: −2+α south: −2−β A = A_q(α,β,γ), b = e_center.

Parameters. α (x-convection), β (y-convection), γ (reaction/shift).

Why use it. Only three parameters are reconstructed no matter how large q becomes. This makes it the cleanest benchmark for the cost of repeated finite-field solves as N grows. It is the family to use when you want N=100–400 without simultaneously exploding the parameter dimension.

P3

RC ladder nodal-admittance system

circuit / degree 2top
N=n · m=2n+3 · degree=2 · tridiagonal
For edges i=1,…,n+1 define yᵢ = gᵢ + s cᵢ. A[i,i] = yᵢ + yᵢ₊₁ A[i,i+1] = A[i+1,i] = −yᵢ₊₁ b = e₁.

Parameters. Laplace parameter s, conductances g₁,…,gₙ₊₁, and capacitances c₁,…,cₙ₊₁.

Why use it. This gives a real transfer-function problem with a very large number of component parameters. The products s·cᵢ make the polynomial entry degree 2 without making the matrix dense.

P4

Mass–spring chain dynamic stiffness

mechanical / resonanttop
N=n · m=2n+2 · degree=2 · tridiagonal
Mass i has parameter mᵢ. Springs k₀,…,kₙ connect the chain to its neighbours/walls. A(z) = K(k) − z M(m) A[i,i] = kᵢ₋₁ + kᵢ − z mᵢ A[i,i+1] = A[i+1,i] = −kᵢ b = e₁.

Parameters. z (squared frequency), masses m₁,…,mₙ, springs k₀,…,kₙ.

Why use it. It is another degree-2 sparse family, but with physically meaningful singular parameter hypersurfaces (resonances). Those singular probes should simply be rejected by the black box, making this a good test of robust probe handling.

P5

Birth–death Markov-chain reachability

probability / many paramstop
N=n · m=2n · degree=1 · tridiagonal
States 1,…,n are transient; 0 and n+1 are absorbing. At state i: move right with pᵢ, left with qᵢ, stay with 1−pᵢ−qᵢ. A[i,i] = pᵢ + qᵢ A[i,i+1] = −pᵢ (i<n) A[i,i−1] = −qᵢ (i>1) b = [0,…,0,pₙ]^T.

Unknown. xᵢ is the probability of reaching n+1 before 0 from state i.

Why use it. This is a scalable application in which both A and b are polynomial in the parameters. It gives 2n interpolation variables while keeping every numerical probe tridiagonal.

Suggested benchmark protocol

1. Use the same finite-field black box for every family. Evaluate every parameter modulo p, build [A|b], and solve the numerical system. Reject a probe only when the evaluated matrix is singular or the modular solve fails.

2. Keep the right-hand side fixed. For S1–S6 and R1–R3 use b=[1,2,...,N]^T. Do not introduce n extra RHS parameters unless that is the experiment you explicitly want.

3. Separate the scaling questions. Use P2 or S4 for matrix-size scaling; S2/S5/S6 for parameter-count scaling; R2/P3/P4 for input-degree scaling; and S1/P1 for rational-output complexity.

4. Record more than wall time. At minimum record N, m, input degree, nnz(A), number of black-box probes, number of rejected/singular probes, time in modular solves, time in univariate reconstruction, time in multivariate reconstruction, and total time.

5. Verify the reconstructed answer. Substitute at one or more fresh random parameter points and check A(α)x(α)=b(α) mod p using points that were not used during reconstruction.

Intentionally omitted from the old page: Cauchy/generalized Hilbert families (rational matrix entries), small fixed 2×2 or 3×3 application sketches, singular kernel systems, and Vandermonde-as-a-benchmark. Vandermonde is useful inside the reconstruction algorithm, but it is a poor primary end-to-end test here because its inverse is unusually explicit and it overlaps with the interpolation backend itself.
